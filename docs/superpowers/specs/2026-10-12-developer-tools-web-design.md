# 开发者工具 Web 站需求设计

## 1. 文档信息

- 文档日期：2026-10-12
- 产品形态：独立 Web 工具站
- 工作名称：Toolbox
- 需求状态：已确认
- MVP 工具：JSON 美化、文本/JSON Diff、时间（戳）转换

“Toolbox”仅作为设计和开发阶段的工作名称。正式命名不影响 MVP 功能验收，可在上线前单独确定。

## 2. 背景

开发者在日常开发、联调和问题排查中经常需要格式化 JSON、比较文本差异、转换时间戳。现有在线工具通常存在功能分散、广告干扰、隐私边界不清晰、移动端体验差等问题。

本产品提供一个轻量、安静、可持续扩展的开发者工具平台。首版只交付三个高频工具，优先保证工具质量和操作效率，不追求工具数量。

长期产品路线为 Web 工具站与浏览器扩展共享工具内核。本期仅开发 Web 工具站，浏览器扩展另行规划。

## 3. 产品目标

1. 用户进入首页后，可在 10 秒内找到并打开目标工具。
2. 三个工具均可在无需登录、无需上传服务器的情况下完成核心任务。
3. 新增工具时，不需要修改首页布局逻辑，只需注册工具元数据和页面路由。
4. 桌面端适合高频开发操作，移动端可完成临时查看和轻量转换。
5. 对数据精度、比较语义和时区语义做明确约束，避免“看似成功但结果错误”。

## 4. 非目标

MVP 不包含以下内容：

- 浏览器扩展、右键菜单、快捷入口和扩展商店发布。
- 用户账号、云端同步、跨设备历史记录。
- 服务端存储、公开分享链接和团队协作。
- API 调试、二维码、编码转换、图片处理等额外工具。
- AI 修复、AI 解释或其他需要联网的智能能力。
- 首页中的工具安装、卸载和版本管理。

## 5. 目标用户与核心场景

### 5.1 目标用户

- 前端、后端、客户端和测试工程师。
- 需要临时处理开发数据的技术用户。
- 偶尔需要转换时间或比较配置差异的非研发用户。

### 5.2 核心场景

1. 联调时粘贴接口响应，检查 JSON 是否有效并格式化阅读。
2. 比较两份配置、日志片段或 JSON 响应，定位新增、删除和修改内容。
3. 将日志中的秒或毫秒时间戳转换为本地时间、UTC 或 ISO 8601。
4. 将指定时区的日期时间转换为秒和毫秒时间戳。
5. 收藏高频工具，并从最近使用区域快速返回。

## 6. 产品结构

### 6.1 页面路由

```text
/                              首页
/favorites                     收藏工具
/tools/json-formatter          JSON 美化
/tools/text-json-diff          文本 / JSON Diff
/tools/timestamp-converter     时间（戳）转换
/about                         关于与隐私说明
```

收藏页复用首页的工具卡片和筛选逻辑。没有收藏时显示空状态，并提供返回全部工具的入口。

### 6.2 信息架构

```text
Toolbox
├── 全部工具
│   ├── 格式处理
│   │   └── JSON 美化
│   ├── 文本对比
│   │   └── 文本 / JSON Diff
│   └── 时间工具
│       └── 时间（戳）转换
├── 收藏
└── 关于
```

## 7. 首页需求

### 7.1 页面结构

首页采用轻量工具目录结构，不使用左侧管理后台导航。

从上到下包含：

1. 顶部导航。
2. 页面标题和隐私说明。
3. 全局工具搜索。
4. 分类筛选。
5. 全部工具卡片。
6. 最近使用。

### 7.2 顶部导航

- 展示品牌标识、全部工具、收藏、关于和主题切换。
- 当前页面入口有明确选中状态。
- 桌面端横向排列。
- 移动端保留品牌、主题切换和菜单按钮，其余入口收纳到菜单。

### 7.3 搜索与筛选

- 搜索匹配工具名称、说明和关键词。
- 搜索不区分大小写，输入后即时过滤。
- 分类包含：全部、格式处理、文本对比、时间工具。
- 搜索条件与分类筛选可以叠加。
- 无匹配结果时展示空状态和“清除筛选”操作。
- 清空搜索后保留当前分类。
- MVP 不提供排序控件。

### 7.4 工具卡片

每张卡片展示：

- 工具图标。
- 工具名称。
- 一句话说明。
- 收藏图标。

交互规则：

- 点击卡片主体进入独立工具页。
- 点击收藏图标只切换收藏状态，不触发页面跳转。
- 图标按钮提供可访问名称和 Tooltip。
- 桌面端三列，平板两列，手机单列紧凑列表。
- 卡片高度在同一行保持一致，收藏状态变化不得引发布局偏移。

### 7.5 最近使用

- 仅存在使用记录时展示。
- 最多展示 5 个工具，按最后打开时间倒序排列。
- 重复打开同一工具只更新时间，不生成重复记录。
- 记录只包含工具 ID 和最后打开时间，不包含用户输入内容。

### 7.6 工具目录注册

首页由统一工具目录元数据驱动：

```text
id
name
description
icon
category
keywords
route
order
```

规则：

- `id` 全局唯一且发布后保持稳定。
- 分类值来自集中定义的分类集合。
- 搜索索引由名称、说明和关键词生成。
- 收藏与最近使用均通过工具 ID 关联。
- 新增工具时只增加目录项和独立页面，不修改首页布局逻辑。

## 8. 工具页公共结构

三个工具页共享以下页面骨架：

- 顶部导航和“返回全部工具”入口。
- 工具图标、名称和简短说明。
- “本地处理”标识。
- 收藏和主题切换按钮。
- 工具操作区。
- 错误、成功和空状态使用一致的视觉语言。

公共行为：

- 工具输入内容默认不写入 Local Storage、IndexedDB、Cookie 或日志。
- 用户离开页面后，不保证恢复输入内容。
- 页面设置可以本地持久化。
- 工具打开时更新最近使用记录。
- 所有主要操作支持键盘访问，并有清晰焦点状态。

## 9. JSON 美化工具

### 9.1 页面布局

- 桌面端使用输入、结果双栏编辑器。
- 移动端按输入、操作、结果顺序纵向排列。
- 输入区可编辑，结果区默认只读。
- 两个编辑器均显示行号、语法高亮和自动换行状态。

### 9.2 核心功能

- 格式化 JSON。
- 压缩 JSON。
- 自动校验 JSON。
- 加载示例。
- 导入 `.json` 文件。
- 清空输入和结果。
- 复制结果。
- 下载结果，默认文件名为 `formatted.json`。

### 9.3 格式设置

- 缩进支持 2 空格、4 空格和 Tab。
- 键名排序默认关闭。
- 缩进和键名排序偏好保存在本地。
- 键名排序递归作用于所有对象，按照键名的 Unicode 码点升序排列。
- 键名排序不调整数组元素顺序。

### 9.4 校验与错误

- 输入变化后进行防抖校验。
- 有效时展示“有效 JSON”状态。
- 无效时展示错误原因、行号和列号。
- 点击错误信息可将编辑器光标定位到错误位置。
- 校验失败时不得覆盖上一次成功结果。
- MVP 只接受严格 JSON，不支持 JSON5，也不自动修复非法输入。

### 9.5 精度要求

- 超出 JavaScript 安全整数范围的数字必须保持原始十进制文本。
- 格式化、压缩和键名排序不得改变大整数值。
- 不得直接采用会造成大整数舍入的解析再序列化流程。

### 9.6 验收标准

- 有效 JSON 可按三种缩进格式输出。
- 压缩结果不包含非必要空白。
- 非法 JSON 可准确定位错误行列。
- `9007199254740993` 经过任意操作后保持不变。
- 导入、复制和下载均能在主流桌面浏览器正常使用。

## 10. 文本 / JSON Diff 工具

### 10.1 页面布局

- 桌面端使用 A、B 双栏编辑器。
- 默认使用并排视图并同步滚动。
- 可切换统一视图。
- 移动端默认使用统一视图，A/B 输入通过标签切换。

### 10.2 公共功能

- 文本和 JSON 模式切换。
- 开始对比。
- 交换左右内容。
- 加载示例。
- 分别导入左右文件。
- 清空内容。
- 展示新增、删除、修改数量。
- 支持上一处和下一处差异导航。
- 使用颜色和符号共同表达差异，不仅依赖颜色。

### 10.3 文本模式

- 默认按行比较。
- 对修改行继续标记行内差异。
- 支持忽略空白；开启后忽略行首、行尾空白，并将行内连续空白视为一个空格。
- 忽略空白不会把有分隔意义的空白完全删除，例如 `a b` 与 `ab` 仍视为不同。
- 支持忽略大小写。
- `CRLF` 与 `LF` 的差异不单独计为内容差异。
- 未开启忽略选项时，空格和大小写差异正常计入。

### 10.4 JSON 模式

- 两侧均通过严格 JSON 校验后才执行结构化比较。
- 按 JSON 路径和数据类型比较。
- 对象键顺序默认忽略。
- 数组元素顺序保留并参与比较。
- 数字、字符串、布尔值和 `null` 严格区分。
- 大整数比较不得发生精度丢失。
- 任一侧解析失败时，明确展示 A/B 侧及错误行列。
- JSON 解析失败后，用户可以切换到文本模式继续比较。

### 10.5 验收标准

- 文本新增、删除和修改可分别识别并统计。
- 差异导航可按顺序循环定位所有差异。
- 交换左右后，新增和删除语义同步反转。
- 仅对象键顺序不同的 JSON 在默认设置下结果为无差异。
- 数组顺序不同的 JSON 结果为存在差异。
- 字符串 `"1"` 与数字 `1` 结果为存在差异。

## 11. 时间（戳）转换工具

### 11.1 页面布局

页面包含：

1. 当前本地时间、秒时间戳和毫秒时间戳。
2. 页面级目标时区选择。
3. 时间戳转日期时间。
4. 日期时间转时间戳。

桌面端两个转换器并排，移动端纵向排列。

### 11.2 当前时间

- 当前时间每秒刷新。
- 秒时间戳按秒刷新，毫秒时间戳可按更高频率刷新。
- 三个动态值使用稳定宽度，刷新不得引发布局偏移。
- 支持暂停和复制。
- “使用当前时间”可将当前值填入两个转换器。

### 11.3 时间戳转日期时间

- 支持自动、秒、毫秒三种单位模式。
- 自动模式仅将 10 位整数识别为秒、13 位整数识别为毫秒，负号不计入位数。
- 其他长度不进行猜测，要求用户手动选择单位。
- 手动指定单位时支持 `0` 和负时间戳。
- 输出目标时区时间、UTC、ISO 8601 和相对时间。
- 每项结果可以单独复制。

### 11.4 日期时间转时间戳

- 输入日期、时间和可选毫秒，标准输入格式为 `YYYY-MM-DD HH:mm:ss.SSS`。
- 支持粘贴带明确时区偏移的 ISO 8601；此时优先采用输入中的偏移，不使用页面目标时区解释。
- 未填写毫秒时按 `000` 处理。
- 输入值按照当前目标时区解释。
- 输出秒时间戳、毫秒时间戳、UTC 和 ISO 8601。
- 每项结果可以单独复制。

### 11.5 时区规则

- 默认使用浏览器系统时区。
- 时区使用 IANA 名称，例如 `Asia/Shanghai`、`America/Los_Angeles`。
- 切换时区只改变日期展示和日期输入的解释，不改变同一时刻的时间戳。
- 自动处理夏令时。
- 输入处于夏令时跳跃导致的不存在时间时，展示明确错误。
- 输入处于夏令时回拨导致的重复时间时，展示两个候选偏移并要求用户选择。
- 本地记录最近选择的时区和单位，不记录输入值。

### 11.6 验收标准

- 秒和毫秒时间戳可正确转换且互相一致。
- 时区切换后，Unix 时间戳不变，日期展示正确变化。
- ISO 8601 输出包含明确时区信息。
- 10 位和 13 位自动识别正确，其他长度给出明确提示。
- 夏令时不存在时间和重复时间均有可理解的处理方式。

## 12. 本地状态

允许持久化：

- 主题偏好。
- 收藏工具 ID。
- 最近使用工具 ID 和时间。
- JSON 缩进与键名排序设置。
- Diff 视图和忽略选项。
- 时间工具的时区和单位偏好。

禁止持久化：

- JSON 原文和格式化结果。
- Diff 左右输入内容和比较结果。
- 用户输入的日期、时间和时间戳。
- 导入文件内容和文件路径。

当目录中某个工具被移除时，读取本地状态需要自动忽略对应的无效工具 ID。

## 13. 数据流与模块边界

### 13.1 模块

```text
应用外壳
├── 路由与导航
├── 工具目录
├── 搜索与分类
├── 收藏与最近使用
├── 通用编辑器组件
├── JSON 处理内核
├── Diff 处理内核
└── 时间处理内核
```

每个工具内核只负责数据处理，不直接依赖页面组件。Web 页面通过稳定接口调用工具内核，以便后续浏览器扩展复用。

### 13.2 数据流

```text
用户输入
  → 页面级校验
  → 对应工具内核
  → 结构化结果或结构化错误
  → 页面渲染
```

输入内容不经过服务端。MVP 可以部署为纯静态站点。

## 14. 错误处理

- 输入错误就近展示，不使用阻塞式弹窗。
- 错误信息包含发生位置、原因和建议动作。
- 复制成功使用短暂状态反馈，不打断编辑。
- 文件读取失败需区分格式错误、文件过大和浏览器权限问题。
- 单个导入文件最大 5 MB；超出后拒绝读取并展示限制说明。
- 处理过程中发生异常时保留用户输入，不自动清空。
- 工具处理失败不得写入最近成功结果。

## 15. 响应式与可访问性

- 桌面端编辑器使用双栏，空间不足时切换为单栏。
- 移动端触控目标不小于 44 × 44 CSS 像素。
- 横向分类在移动端可滚动，不压缩文本。
- 所有按钮、输入框、标签和错误信息具备语义化标记。
- 键盘用户可完成搜索、收藏、编辑、执行、复制和差异导航。
- 焦点状态清晰可见。
- 文本与背景达到 WCAG 2.1 AA 对比度要求。
- 尊重 `prefers-reduced-motion`，不依赖动画传达状态。
- 差异状态同时使用颜色、符号和文本语义。

## 16. 性能与兼容性

- 首页只加载目录和首页组件，三个工具页面按路由懒加载。
- 编辑器和处理依赖不得阻塞首页首屏。
- 2 MB 以内输入在主流桌面设备上应保持可交互。
- 长任务需要避免阻塞主线程；必要时使用 Web Worker。
- 支持当前稳定版及前一个稳定版的 Chrome、Edge、Firefox 和 Safari。
- 不依赖服务端即可完成全部 MVP 功能。

## 17. 隐私与安全

- 页面明确展示“本地处理”。
- MVP 不采集用户输入内容、转换结果或导入文件。
- MVP 不接入第三方广告和第三方内容分析脚本。
- 不将输入内容拼接到 URL、页面标题或错误上报字段。
- 下载文件由浏览器本地生成。
- 关于页面说明本地存储项目及清除方式。

## 18. 测试要求

### 18.1 单元测试

- 工具目录搜索、分类和排序。
- 收藏和最近使用状态。
- JSON 格式化、压缩、错误定位和大整数。
- 文本 Diff、JSON 结构 Diff 和差异统计。
- 秒/毫秒转换、IANA 时区和夏令时边界。

### 18.2 组件测试

- 首页搜索、分类、收藏和空状态。
- 工具页工具栏和设置状态。
- 编辑器错误定位、复制和下载。
- Diff 差异导航与视图切换。
- 时间转换结果刷新与复制。

### 18.3 端到端测试

- 从首页搜索并进入每个工具。
- 完成三个工具的核心流程。
- 刷新页面后偏好保留、输入内容不恢复。
- 桌面和移动视口下无溢出、遮挡和不可达操作。
- 仅使用键盘完成主要流程。

## 19. MVP 上线验收

满足以下条件后可判定 MVP 完成：

1. 首页、收藏页、关于页和三个工具页均可访问。
2. 首页搜索、分类、收藏和最近使用符合本文规则。
3. 三个工具的核心流程和错误状态全部通过验收标准。
4. 所有处理在浏览器本地完成，输入内容未被持久化或上传。
5. 桌面端和移动端主要流程可用。
6. 无阻断级可访问性问题。
7. 核心单元测试、组件测试和端到端测试通过。

## 20. 后续规划

### 20.1 Web 工具扩展

后续可按目录注册机制增加编码转换、正则测试、二维码、URL 处理、图片处理和 API 调试等工具。

### 20.2 浏览器扩展

浏览器扩展单独立项，优先复用三个工具内核，再规划：

- 扩展弹窗和独立标签页入口。
- 页面右键菜单。
- 浏览器快捷键。
- 选中文本后直接发送到工具。
- 扩展权限最小化。

浏览器扩展不得反向要求 Web MVP 增加扩展专属 UI。

## 21. 已确认决策

- 总体路线为 Web 工具站加浏览器扩展，本期只开发 Web。
- MVP 只包含三个工具。
- 首页采用轻量工具目录，不采用侧栏管理控制台。
- 首页通过统一工具元数据扩展。
- 每个工具使用独立 URL 和独立工作区。
- 用户输入默认只在内存中处理。
- JSON 必须保证大整数不失真。
- JSON Diff 忽略对象键顺序、保留数组顺序。
- 时间工具支持秒、毫秒、IANA 时区和夏令时边界。
